## Container restarts: the failure mode that has cost the most time

This remote session's container has restarted at least four times, and each restart rolls the
disk back to a snapshot. Symptoms: background tasks vanish, `uptime` shows a minute, untracked and
uncommitted files are gone, sometimes local commits too. Rules that came out of it:

1. Before any work after a restart: `git fetch origin <branch>` and fast-forward (or rebase your
   own commit onto origin). Verify the tree carries the later work before trusting it.
2. Push after every finished unit of work, not at the end. Anything unpushed is provisional.
3. Build agents commit and push their own files at milestones (the v3 script does this).
4. Workflow journals cache finished agents' return values, not their files. A resume returns the
   cached value and rebuilds nothing. Check `journal.jsonl` before assuming there is anything to
   recover.
5. The progress artifact and the mock book are hosted artifacts and survive restarts.
